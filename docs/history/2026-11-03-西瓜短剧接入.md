# 西瓜短剧接入（uxbu.j4g3wltg.cc）：一个纯 JSON 源，和四个静默坑

2026-11-03。目标：把 `https://uxbu.j4g3wltg.cc/` 做成 spider 源。结论先说 ——
**这是目前最省事的一类站**：裸 `curl` 就 200，全套接口不鉴权、不要 cookie、不要签名，
没有任何一条 HTML 需要正则去啃。真正花时间的不是「怎么抓」，是四个**静默失败**：
每一个都表现为「看起来通了，用起来不对」。

## 一、站点形状

站点自称「西瓜短剧」，AI 成人短剧平台，前端是 require.js + 服务端渲染的混搭
（列表页首屏 SSR，翻页走 AJAX）。后端和黄果短剧是同一套（`/api/videos/<id>`、
`/api/videos/<id>/play?ep=N`、同一对 AES 封面密钥），只是路由多了一层
`/api/videos/category/<拼音 slug>`。

裸请求实测（手机 UA，无 cookie）：

| 端点 | 形状 |
|---|---|
| `GET /api/home` | `banners[4] / featured[8] / latest[8] / cate_rec[4] / topic_rec[2]` |
| `GET /api/videos?page=&size=` | 全站最新，`{items, pagination{page,pages,size,total}}` |
| `GET /api/videos?cate_id=<id>&page=&size=` | 按数字分类（24/25/26/27） |
| `GET /api/videos/category/<slug>?page=&size=` | 按频道 slug（ai-duanju 等） |
| `GET /api/search?q=<kw>&page=&size=` | 搜索，`engine: vector`，pagination 同形 |
| `GET /api/videos/<id>` | 详情 + `episodes[{ep_num,title,duration,status}]` |
| `GET /api/videos/<id>/play?ep=<n>` | `video_url`（H.264 m3u8）+ `video_url_hevc`（H.265，可选） |
| `GET /api/tags` | `categories[].tags[]`，3 组有内容 / 45 个标签 |
| `GET /api/ranks/hot` | 榜单 20 条（没接） |

分类对应：`ai-xiguanyuanchuan`=26 西瓜原创、`ai-duanju`=24 AI成人短剧、
`ai-manju`=25 AI成人漫剧、`ai-mogai`=27 AI魔改。

## 二、四个静默坑

**① `status` 不是 HTTP 状态，而且 HTTP 永远 200。**
成功是 `status:1 + msg:''`；失败是 `status:0 + msg:"该集不存在或已下架" + data:[]`，
HTTP 照样 200。所以「非 2xx 就报错」在这里一条都拦不住 —— 播不了的时候接口是
「成功」的，只是 data 是空数组。判失败只能看 `status`，或者看 data 形状。

**② 播放地址带 `auth_key` 签名，只能现取。**
`?auth_key=1793636235-0-0-<md5>` 里那个数字是**签发时刻**，不是过期时刻
（有效期由 CDN 定）。所以 play 必须每次请求 `/play?ep=N`，零缓存。缓存一次的表现
是「过几小时点开 403」，而那个报错在用户眼里像「没有权限」。

**③ `/api/videos?tag=<slug>` 是个假参数。**
传了也返回全站 —— 带 tag 和不带 tag 的 `total`、`items` 逐条相同（都是 573）。
所以「标签页」不能走接口，只能退回站点自己的 SSR 页 `/tag/<slug>/page/<n>/`
（后入 151 条，每页 20）。这条如果没量过，验收时看到「点后入出来一堆别的东西」
才反应过来，而那时已经上线了。

**④ 封面是 AES-CBC 加密图，且首页给的是相对路径。**
`pic.drleao.cn` 返回 `binary/octet-stream`，不是 JPEG。密钥和黄果同源：
`key=f5d965df75336270` / `iv=97b60374abc2fbe1`，`AES/CBC/NoPadding`，解密后
JPEG 是 `ffd8ffe0`、PNG 是 `89504e470d0a140a` —— 第 6 字节 `0x14` 本该是 `0x1a`，
正是 `headerRepair: legacy-xor` 修的那一位（`0x14 ^ 0x0E = 0x1a`）。
另外首页接口的 `cover` 是 `/upload_01/upload/…` 相对路径**且不带 auth_key**
（列表接口给的是完整签名地址），不补 PIC 前缀首页就是一片灰。

顺带一条：51cg 用的是同一个 key、另一个 iv（`97b60394…`）。说明这家图床按批次换 iv ——
以后接同图床的新站，别照抄 iv，去页面 JS 里找 `decryptImage`。

## 三、播放链

`video_url` 是 HLS，master 在 `yd-hls.hzjvlo.cn`（`/videos5/…` 与 `/m3m/rr142/m3u8-v5/…`
两种路径），m3u8 里带 `#EXT-X-KEY:METHOD=AES-128`，分片和 `crypt.key` 在
`tp3.drleao.cn`。两个域都要写进配置的 `http.hosts`，漏一个的表现是「列表能看、
一播报格式不支持」。

H.265 只有部分片子转好了（抽查 6 个视频，2 个有）——所以配置里列两条线路，
`play` 里按实际返回决定给几条，用户选 H.265 而那集没有时回落 H.264 并给一句 note。

## 六、还没做的

- **没上服务器**：配置和 js 要传到 `/srv/cfg/spiders/`，市场清单加一条，才算对用户可见。
  这一步要人执行，见 `docs/源市场清单.md` 第五节。
- **没上真机**：离线回归只证明「解析对」，证明不了 libVLC 认这条 AES-128 HLS。
  真机验收看 `adb logcat -s HG.Spider`，重点是 `cap=play ok` 和起播不报格式错。
- **`net` 故意没写**：站点在 Cloudflare（LAX 边缘），裸请求 200 无挑战，播放 CDN 在境内。
  跟随全局开关最灵活。真机若出现「首页 45 秒超时」，才是改成
  `declared + proxy: ["uxbu.j4g3wltg.cc"]` 的信号（只代理入口域，CDN 仍直连）。
