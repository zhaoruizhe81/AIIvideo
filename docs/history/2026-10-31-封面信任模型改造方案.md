# 封面信任模型改造方案：让信任由响应决定，而不是由名单决定

**状态**：已按本方案实施 P1+P2+P3（2026-10-31 深夜，当晚评审通过）。§十的开放问题按方案自身倾向收口：观测集按源隔离；C 档裸拉带 `Referer: <源 origin>`、绝不带 cookie；参数记忆按 `(源, path)` 路径级；诊断入口仅 debug 构建可见（设置页按 `app-version.debug` 门控）。P4（porn91 精确主机补齐）未做。发版仍排在实现与真机验证之后——线上配置一个字没动。

## 一句话

把「封面域名可信」从**人维护的名单**改成**由源响应观测出来的事实**：首次见到的公网 HTTPS 封面主机用**裸请求**试拉一次，拉得动就记住，拉不动就不信；名单（`allowedHosts`）从「唯一的门」降级为「安全地板 + 想钉死时的工具」。

---

## 一、背景：这个问题的本质是「时序错配」

三处错误表面不同、错误方式相同——**把会变的事实存成了不变的事实**：

| 事实 | 存成了什么 | 时间尺度错在哪 |
|---|---|---|
| 哪些图床域可信 | `allowedHosts` 配置快照 | 图床二级域六随机字符轮换，两周一次；名单是加源那一刻的 |
| 现在能不能拿到这张图 | 主机级负缓存，5 分钟 | 网络抖动是秒级现象，5 分钟的粒度把「刚才抖了一下」记成了「现在坏了」 |
| 这是哪张图 | 缓存键把 `auth_key` 算进去 | 签名 90 分钟一轮，等于身份每 90 分钟换一次 |

用户看到的是灰块，系统里没有任何一环能回答「此刻为什么没封面」——失败被负缓存合并、被 `Report.Once` 挡住，最后落地为一片灰。重启能修好，恰好证明系统缺的不是修复能力，是**重新判断的能力**。

### 已经修掉的两层（2.0.28，2026-10-31 19:46 包，全源生效）

- **负缓存分档**：网络类主机冻结 45 秒（`FAIL_HOST_NET_MS`），配置类冻满 5 分钟；成功即 `forgetFailure()` 销账。
- **缓存键剔签名**：`cacheKeyQuery()` 剔除 `auth_key` / `sign` / `signature` / `token` / `expires` / `oss*` 七类参数，同一路径按业务参数命中。

这两条是代码级、全源共用的，「一次抖动黑五分钟」和「每 90 分钟整座图床重下一遍」的放大器已经拆掉。

### 还没修的一层（本方案要解决的）

`allowedHosts` 仍是**每份源各自维护的精确主机名单**，而线上所有源（含 51cg / mrds66 / 黄果 / porn91 这族）现在写的全是精确值。通配语法（`pic.*.cn`）已在代码里，但没有一份配置在用；即便用了，它也只是把「观测到的轮换形状」固化成规则——换 TLD、换前缀、换层数，一样灰。

**只按现象修（补域名、加提示、让用户重装），下次换个图床或换个签名参数，同样的灰还会回来。所以要动机制。**

## 二、现状盘点（改造前）

| 组件 | 位置 | 现在的行为 |
|---|---|---|
| 白名单校验 | `SiteProfile.coverUrl()` | `host ∈ allowedHosts`（精确或单层通配），否则抛「无效封面域名」 |
| 白名单语法 | `SiteProfile` 校验段 | 支持单星通配，`*` 不许在首尾、不许连写；写错整份源拒掉 |
| 封面取数 | `SiteRepository.coverData()` | 负缓存检查 → `coverUrl()` 归一化 → 取数（带源 header、走源路由）→ 解密 → 缓存 |
| 缓存键 | `SiteRepository.coverData()` 内 | `sha256(fingerprint:host:path?cacheKeyQuery(query))` 前 16 字节 |
| 前端 | `assets/cover.js` | `cover.get(url)` → 桥命令 `cover` → 返回解密后字节 |
| 桥 | `MainActivity` 命令表 | `cover` → `repository.coverData(url)` |

## 三、目标与非目标

**目标**

1. 图床轮换**不再需要任何人跟**——新主机由响应自动进入可信集合，源码不用改、配置不用改。
2. 白名单仍是**安全地板**：非 HTTPS、字面 IP、`.local`、私网、带 userinfo 的地址一律拒。
3. 可信集合是**有界、有 TTL、可观测**的，不会变成第二个需要人维护的名单。
4. 封面失败的最终形态（灰块）**可归因**：本地诊断能回答「此刻为什么没封面」。

**非目标**

- 不做「任意 URL 都能代理」：只放开封面这一条取数通道，播放地址/字幕/密钥不受影响。
- 不改源配置格式：`allowedHosts` 语义保持，老配置照旧可用。
- 不追求零误报：轮换后的第一次请求可能失败（见风险 §八），可接受。

## 四、设计

### 4.1 信任三档（核心）

`coverUrl()` 的判定从「∈ allowedHosts」改成三档：

| 档 | 条件 | 取数行为 | 进入方式 |
|---|---|---|---|
| **A 声明信任** | `host` 命中 `allowedHosts`（精确或通配） | 现状不变：带源 header（UA/Referer/源声明的 cookie）、走源声明的路由、可用 `hostRewrites` 钉 IP | 配置写出 |
| **B 观测信任** | `host` 在**该源的观测集**里且未过期 | 同 A | 首次裸拉成功（见 4.2） |
| **C 未知主机** | 以上都不命中 | **裸 GET**：不带源 header、不带 cookie、走默认路由；成功（能解出图片）→ 写入观测集；失败 → 按网络类失败记 45 秒冻结 | 源响应里第一次出现 |

硬性拒绝（所有档，任何来源都不放行）：非 `https`、字面 IP、`.local` 后缀、解析到私网段、带 userinfo、带 fragment、host 超长。

### 4.2 观测集 `CoverTrustStore`

**数据结构**（按源 fingerprint 隔离，SharedPreferences）

```json
{ "host": "pic.nhqktz.cn", "firstSeenAt": 1793000000000, "lastSeenAt": 1793000000000,
  "ok": 3, "fail": 0, "tier": "C" }
```

**生命周期**

- 写入：C 档裸拉成功后。上限 **32 条**，满了删 `lastSeenAt` 最老的。
- 命中：B 档请求成功 → `lastSeenAt`/`ok` 刷新；失败 → `fail+1`，连续 3 次失败降级回 C 档（重新裸拉验证），不直接删。
- 过期：`lastSeenAt` 超过 **7 天**未命中即清理。
- 重置：换源（`SiteProfile` 指纹变化）时整份作废——复用现有换源 reset 路径；「恢复出厂设置」一并清掉。
- 上报：某主机**首次**进入观测集时上报一条（kind=`cover_host_trusted`），服务端据此观察轮换族，不用再靠人翻日志。

**为什么这个缓存不会变成「第二次把事实存死」**

- 输入是源自己的响应（事实），不是拍脑袋名单；
- 有界（32）+ 有 TTL（7 天）+ 失败降级三件套，防止它退化成永久豁免；
- 每次进入都有上报，可被服务端审计。

### 4.3 C 档裸拉的取舍（安全边界）

裸拉 = 不带 Referer/UA/源 cookie，只发一个最普通的 GET。这样做的前提判断：

- **能泄露的只有「我们拉了这个地址」**，拉回来的字节只用于解图；不带任何凭据，无法借道外传。
- 首拉**不带 Referer** 的代价：防盗链站点会 403，轮换后的第一次因此失败。折中：允许带 `Referer: <源 origin>`（Referer 本身不是秘密，且防盗链通常只认它），**但绝不带 cookie**。这条走真机验证（见 §七）。
- 私网/IP 直连在 DNS 之后二次拒绝，避免 DNS rebinding 那类把公网域名解析到内网的情况。

### 4.4 身份函数动态化（替换静态签名名单）

现状 `SIGNATURE_PARAMS` 是**本次观测到的签名参数名**，下一个图床用 `e=` / `X-Oss-Expires` 之流就漏。改成自适应：

- 按 `(源 fingerprint, path)` 记录每个 query 参数的**最近 3 个值**（有界）；
- 同一 path 下某参数的取值出现过两个不同值 → 判定易变 → 从缓存键剔除，并**持久化**这条判定；
- 现有 7 个名字保留为**种子**（冷启动时立刻生效），自适应在其上增量。

语义：键只由「决定内容的东西」构成，且这个判断会随着观测自己演进。

### 4.5 可观测性：让灰块成为一个可回答的问题

- **前端**：`cover.js` 渲染占位时，把失败原因（冻结中 / 配置拒绝 / 解密失败 / 404）随一次上报带上来，按「页面灰块数」计数，而不是按「请求失败数」计数——后者漏掉被负缓存拦住、根本不发请求的那批。
- **本地诊断**：设置页加一个「封面诊断」入口（仅 debug 或长按版本号开启），显示：当前观测集内容、最近 20 条失败与原因、当前冻结中的主机及剩余秒数。这是回答「此刻为什么没封面」的最短路径。
- 服务端：`cover_host_trusted` + `cover_placeholder` 两类事件，前者看轮换族，后者看灰块规模。

### 4.6 通配语法的新定位

`pic.*.cn` 保留，但**不再是轮换的必需手段**，只作为「我就是要钉死这一族」的显式声明。有了 4.1 的 C→B 自动信任，配置里继续写精确主机也不会影响新客户端；老客户端则继续吃现在的精确名单（今晚已补齐三源）。**因此本方案不再有「发版后等采用率再改配置」的强顺序依赖**——配置可以一辈子不动。

## 七、测试与验收

**单测（JVM）**

- `CoverTrustStore`：写入/上限淘汰/TTL 过期/失败降级/换源清空。
- `SiteProfile.coverUrl()`：A/B/C 三档各放行一次；非 https、字面 IP、`.local`、userinfo、私网全部拒绝。
- `cacheKeyQuery()`：种子参数剔除；新增易变参数在第二次观测后被剔除；稳定参数保留。
- 回归：现有 `CoverBlankUrlTest` / `CoverFailureCacheTest` 全绿。

**真机（7f8f5254）**

1. 把某源一份配置的 `allowedHosts` 临时改成不存在的域（模拟轮换）→ 首拉失败、45 秒后再试；把响应里的封面 host 换成真实新域 → 首次裸拉成功 → 进入观测集 → 后续带 header 正常。
2. 换源 → 观测集清空（诊断页可见）。
3. 灰块场景：断网刷新列表 → 占位出现 → 诊断页能看到「冻结中 + 剩余秒数 + 原因」。
4. 老配置（精确主机）行为不变：三源各刷一页，封面正常。

**验收标准**：模拟轮换后**不改配置、不重启**，第二屏起封面自动恢复；诊断页能对任意一块灰给出原因。

## 八、风险与回滚

| 风险 | 影响 | 处置 |
|---|---|---|
| 观测集变成信任垃圾场 | 恶意/畸形源塞入大量主机 | 上限 32 + TTL 7 天 + 首次上报，服务端可审计 |
| 裸拉被防盗链挡 | 轮换后第一次失败，用户体验仍是「等一下」 | 允许 `Referer: origin`；真机验证；失败按 45 秒冻结，不放大 |
| 私网域名解析绕过 | 被借道探测内网 | 字面 IP 直接拒；解析后私网段二次拒；只认 HTTPS |
| 自适应误判稳定参数为易变 | 缓存命中率下降（多下载） | 三次观测才落判定；误判只损失缓存，不影响正确性 |
| 观测集与 cached 键记忆写盘太频繁 | IO 抖动 | 批量/合并写（沿用 `AppStore` 的 apply 风格），单条上限 |

**回滚**：观测集与参数记忆都是独立 SharedPreferences 键，清空即回到现状行为；代码层可先只上 A 档兜底（B/C 档开关关闭）。

## 九、和发版的关系（定序）

本方案**不依赖发版顺序**：不要求把线上配置改成通配，因此不存在「老客户端读到通配把整份源判非法」的风险。执行顺序是：

1. 评审本方案 →
2. 实现 P1（+P2/P3）→
3. 全量单测 + 真机验证 →
4. 出 2.0.29（versionCode 20029）→
5. 观察 `cover_host_trusted` / `cover_placeholder` 两类上报，确认轮换自愈在真实流量里成立。

第 4 步之前，线上配置**一个字都不用动**。
