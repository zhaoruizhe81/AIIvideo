# 冷启动封面全灰：把「核心还没起来」误判成「没有代理」

> 2026-11-08。欧乐影院接入后真机反馈「封面都看不见了」（首页全是首字占位），
> 但接口、播放都正常。查下来不是源的问题，是 **App 路由层在冷启动瞬间把必须走代理的
> 封面域判成了直连**，触发 geo 403，再被封面失败缓存冻住 5 分钟。

## 症状

- 冷启动后首页封面全是占位字（`寒`/`斗`/`光`…），少则几分钟不恢复。
- `adb logcat` 里：
  ```
  [source] 路由 static.olelive.com → 直连
  java.io.IOException: HTTP 403 @ https://static.olelive.com/upload/vod/...jpg_384x560.jpg
  SiteRepository$CoverFailure: 封面主机刚刚失败过（static.olelive.com），本轮不再重复上报
  封面加载失败 xxx static.olelive.com 图片无法解码 @227
  ```
- 但**同一台手机、同一个 SOCKS 代理端口**，`curl --socks5 127.0.0.1:PORT` 取同一张图是 **200**。
  说明代理出口没问题，是 App 自己没走代理。

## 根因链（缺一不可）

1. 冷启动时 `内置核心已启动 → hysteria2` 的日志比首批封面请求晚 **~0.2s**（实测：
   封面 `12:33:39.05`，核心 `12:33:39.23`）。前端启动即从本地缓存渲染首页并开始拉封面，
   不等代理核心。
2. `AiiHttp.initialRoute()` 先看 `NetRoute.directOnly(host)`；`directOnly` 里有
   `proxyUnavailable(...)`：**源声明该域走代理、但 `effectiveProxy()` 是空串 → 判定「没有代理可用」**，
   于是 `directOnly=true` → 直接走直连。
3. 可冷启动那一瞬间 `effectiveProxy()` 空，不是「没有代理」，是「**核心还没 listen**」。
   拿直连去撞欧乐这种 geo 站 → **403**。
4. `routeAndSend` 只在**连接失败**（connect refused/reset）时才换路；**HTTP 403 是业务响应，
   不触发换路**，于是这条请求就这么死在直连上。
5. 更狠的是封面失败缓存：`SiteRepository.rememberFailure` 对**每个失败 URL 冻 5 分钟**
   （`FAIL_CACHE_MS`），主机层冻 45s。冷启动那一波每张封面都吃一次 403，整页灰 5 分钟。
6. 结果：核心其实 0.2s 后就绪、代理完全可用，但封面已经被判死。

> 一句话：**把「核心启动中」当成了「没代理」，直连 → geo 403 → 5 分钟冻结。**

## 修复

`NetRoute.proxyUnavailable()`：内置核心模式下不再把「代理串为空」当成「没有代理」，
返回 `false`，让请求走代理分支；代理分支的 `routeForProxyHost()` 本来就会**等核心就绪**
（`PROXY_READY_WAIT_MS=2500`）。核心真起不来时，`routeAndSend` 会按老逻辑换路直连兜底。

```java
// NetRoute.proxyUnavailable
if (AiiHttp.builtinMode()) return false;          // 核心启动中 ≠ 没有代理
return AiiHttp.effectiveProxy().length() == 0;
```

新增 `AiiHttp.builtinMode()`（区分内置核心模式；:spider 进程认 `processProxyMode`，
主进程读 `proxyMode`）。

### 为什么只改这一处就够

- 封面（`SiteRepository.coverData` → `AiiHttp.get(profile)`）、接口（spider `net`）、
  播放取流（`VlcRelay`）最终都问 `NetRoute`。改这里，三类请求一起受益。
- 单元测试环境 `proxyModeOrEmpty()` 返回空串（非 builtin），`proxyUnavailable` 行为不变，
  `NetRouteTest` / `AiiHttpRouteTest` / `EffectiveProxyTest` / `ProxyRouteTest` /
  `RouteMemoryTest` / `XrayConfigRoutingTest` 全绿。

## 验证

- 修复后冷启动：`HTTP 403 @ static` / `封面加载失败` / `图片无法解码` **计数 0**，首页封面
  轮播+推荐全部出图。
- `./scripts/build.sh test` 全量通过。

## 附：这次为什么「有时好有时坏」

冷启动时封面请求与代理核心启动是**赛跑**：核心先就绪 → 封面走代理 → 正常；封面先发 →
判直连 → 403 + 5 分钟冻结。所以偶发「这次有图、下次全灰」，不是站点波动。
