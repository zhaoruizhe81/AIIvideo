# 站点配置参考

一份 JSON，描述三件事：**去哪取数据、响应里哪个字段是什么、界面长什么样**。

APK 里不带任何站点信息。装完是空的，用户自己填一个 https 地址，App 拉下来校验通过才存。

---

## 文件在哪

| 角色 | 路径 | 谁写 |
|---|---|---|
| 内置模板 | `work/android/app/src/main/assets/site-default.json` | 打包时进 APK。改它要重新打包 |
| 用户配置 | `/data/data/com.huangguo.mobile/files/user-source.json` | 设置页 →「内容源」→ 填地址 → App 拉取并校验后写这儿 |
| 源清单 | `/data/data/com.huangguo.mobile/files/user-sources.json` | 只记「存过哪些地址」，配置内容不在这儿 |
| 前端可见的那份 | `assets/site-web.js` | 构建产物，由 `gen-web-config.py` 从内置模板生成，**不要手改** |

浏览器读不了 JSON（页面 CSP 是 `connect-src 'none'`），所以 `web` 那一块会被包成 `window.HG_SITE = {...}` 以 `<script>` 载入。

### 继承规则（先看这条）

运行时 `SiteProfile` 把用户配置**递归合并**到内置模板上：

- **对象**：逐键合并。你只写 `web.ui.categoryIds`，那 `web.ui` 里别的键还是内置那份
- **数组和标量**：整块替换。你写了 `web.ui.tabs`，内置那两个 tab 就没了

推论，都是实测撞过的：

```text
用户配置没写 ui.tabs          → 模板里有什么就还是什么
用户配置写了 ui.categoryIds   → 模板里已有的 key 会**并存**，不会因为你没写就消失
用户配置写了 ui.tagGroups     → 整块替换，模板那几组一个不留
```

2026-10-19 起模板（`site-default.json`）的 `web.ui` 是空的：默认导航和分类胶囊都不替
源决定。所以现在的实际效果是「不写就是没有」，上面三条只在你自己写了两层配置时才会
咬人。

所以配置里「空数组」和「不写」是两个意思：空数组 = 我要清掉它，不写 = 用默认。

## 最小可用配置

REST 型站点（自己有接口）的最小一份：

```json
{
  "origin": "https://example.com",
  "web": {
    "categories": { "hot": 1, "new": 2 },
    "paths": {
      "home": "/api/home",
      "detail": "/api/videos/{id}",
      "episode": "/api/videos/{id}/play?ep={episode}",
      "search": "/api/search?q={keyword}&page={page}",
      "category": "/api/videos?cate_id={cateId}&page={page}&size={size}",
      "tags": "/api/tags"
    }
  }
}
```

`cover` 那块不写也行 —— 不写就按 `mode: "plain"` 处理，封面直接当图片用。写 `aes-cbc` 就必须给 `key` 和 `iv`。

## 还有一种地址：源清单

上面讲的是**一个源**。设置页那个输入框还接受**一份源清单**：

```json
{
  "updated": "2026-10-18",
  "sources": [
    { "name": "影视线路 1", "desc": "44 个分类", "url": "https://cj.lziapi.com/api.php/provide/vod/" },
    { "name": "Hanime1", "desc": "里番 / 需代理", "url": "https://hanime1.me/" }
  ]
}
```

清单里装的是源**地址**，不是一个配置，所以它不会被存成 `user-source.json` ——
`load()` 认出 `sources[]` 就抛 `MARKET_SOURCES`，前端把里面的站点列出来让用户勾，
勾一条存一条。自己维护一份清单看[源市场清单](源市场清单.md)。

## 顶层字段

| 键 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `origin` | string | 否 —— 留空时 `paths.home` 必须是绝对 https 地址 | 站点入口。**只能是裸 https 域名** —— 带路径、查询串、`#`、用户名密码一律拒绝。它唯一的作用是拼在**相对** `paths` 前面；绝对地址不看它（见 `web.paths` 那节的两张情况表） |
| `headers` | object | 否 | 请求头模板，值里的 `{origin}` 会替换成实际域名 |
| `doh` | object | 否 | 自定义 DNS 解析，见下 |
| `cover` | object | 否 | 封面解密。不写 = 原样当图片用（等同 `mode: "plain"`） |
| `web` | object | 是 | 前端配置，见下 |
| `adapter` | string | 否 | `"cms"`（苹果CMS 族）或 `"agedm"`（AGE动漫）。**这是「一个适配器覆盖一个族」的地方，不是每个站一份** —— 详见 `work/android/app/src/main/java/com/huangguo/mobile/CmsAdapter.java` 头上的说明。写别的值会被明确拒掉 |
| `api` | string | `adapter=cms` 时必填 | CMS 接口地址，https |
| `_note` | string | 否 | 自述。下划线开头的键都会被校验和检查忽略 |

### `headers`

```json
"headers": {
  "User-Agent": "Mozilla/5.0 (Linux; Android) AppleWebKit/537.36 Chrome/130 Mobile Safari/537.36",
  "Referer": "{origin}/"
}
```

只对 REST 型站点的普通请求生效。CMS 那条线走的是另一个「朴素客户端」，不套这份模板（CMS 接口不需要伪装）。

### `doh`

```json
"doh": {
  "enabled": true,
  "servers": [
    { "name": "阿里DNS", "url": "https://dns.alidns.com/resolve", "ips": ["223.5.5.5", "223.6.6.6"] }
  ]
}
```

它的作用不是「救黑名单域名」，而是**拿到某个域名的全部 IP 交给 OkHttp 轮询**，以及绕开运营商那一跳。`ips` 必须写：DoH 服务器自己也得先解析，不写就递归了。

解析结果会落盘（`aii-dns` 这个 SharedPreferences），TTL 30 分钟，命中时直接用旧地址并在后台重问一次。

### `cover`

| 键 | 默认 | 说明 |
|---|---|---|
| `mode` | 不写 = 不解密 | `plain` / `aes-cbc` / `auto`。`auto` = 试一下像不像图片，不像才解 |
| `allowedHosts` | `[]` | **白名单。精确主机，或单层通配（`pic.*.cn`，2.0.29 起）。写了 `cover` 就得给，空数组会让 App 启动就崩** |
| `hostRewrites` | `{}` | `{"旧域名": "新域名"}`，取图前改域名 |
| `transformation` | `AES/CBC/NoPadding` | 解密算法 |
| `key` | — | 16 字节十六进制字符串 |
| `iv` | — | 同上 |
| `keyEncoding` | `text` | 密钥怎么解释 |
| `checkExtension` | `true` | 按扩展名判断要不要解密 |
| `headerRepair` | `legacy-xor` | 头几个字节的修补方式 |
| `bytePatches` | `[]` | 定点字节替换 |

`allowedHosts` 是硬闸：`SiteProfile.coverUrl()` 对不在表里的域名**直接抛异常**（`无效封面域名`），不是降级。自动生成的 CMS 配置会从探测结果里把封面域名提出来填进去；手写配置遇到「封面全是占位图」先查这一项。

通配只支持**一个**星号、**一层**，位置在中间：

| 写法 | 放过 | 不放过 |
|---|---|---|
| `pic.*.cn` | `pic.sugfew.cn`、`pic.drleao.cn` | `pic.a.b.cn`（跨了两层）、`evilpic.sugfew.cn`（前缀不对）、`pic.x.com`（后缀不对） |
| `*.cn`、`pic.*`、`pic.*.*.cn` | — | 全部：这三种模式在加载源时就被判「无效封面域名」 |

为什么值得用：2026-10 出现的一族加密图床在 51cg / mrds66 / 黄果之间共用，二级域六个随机字符换来换去（`drleao` → `gyezbp` → `sugfew` → `nihmcl`）。每换一次，没跟上的设备看到的就是「这个源没有封面」，而唯一的线索只有日志里一行被拒的主机名。写成 `pic.*.cn` 就不用再跟了。

`*` 不许放首尾、不许连写，是为了让模式自己把范围钉死在一个标签上 —— 白名单是 SSRF 那道闸，放宽一档得说得出放宽到哪儿为止。

## `web.paths` —— 动作词汇表

路径不是「站点的真实路径」，而是 **App 内部的九个动作**。前端按动作名查表拿模板，填完占位符再发出去。

### 每条路径要么是 `/` 开头的相对路径，要么是 `https://` 绝对地址

所有 REST 请求都从 `fetchApi()` 借 `detail` 桥送进 Java，`SiteRepository.detail()` 里判两件事：

```smali
# 先判绝对地址 —— 它不以 / 开头，放在「/ 开头」那条后面会被误杀
const-string v0, "https://"
invoke-virtual {p1, v0}, startsWith
if-nez v0, :detail_absolute        # 是绝对地址 → 直接用
const-string v0, "/"
invoke-virtual {p1, v0}, startsWith
if-eqz v0, :detail_html            # 不是 / 开头 → 报错
# → origin + 路径
```

两条都不满足，抛出来的是这句：

```text
路径既不是 / 开头的动作路径，也不是 https 绝对地址，无法处理
```

（2026-10-16 之前这里只认 `/api/` 开头，报的是「detail 已改为纯 REST，抓 HTML 的分支已移除」—— 提示词和真实原因完全无关。已经改掉了。）

### 相对路径才拼 `origin`；绝对地址直接用

```text
origin = "https://example.com"
paths.home = "/api/home"                          → https://example.com/api/home
paths.home = "https://api.other.com/v2/home-list" → 原样使用（不看 origin）
origin = ""（空）
paths.home = "/api/home"                          → /api/home 原样交给适配器
```

**留空 `origin` 是给两种场景用的：**

1. **接口在别的域名上**，或同域但不在 `/api/` 下面 —— 直接把完整地址写进 `paths`。留空的前提是 `paths.home` 得是绝对地址，否则首页不知道去哪取（这条 `validate()` 会拦）。
2. **写适配器时** —— 苹果CMS 就是这样：`origin` 空，`/api/home` 原样交给 `CmsAdapter`，由它拿 `api` 字段去拼真实地址。

### 九个动作

| 动作 | 何时调 | 必填 |
|---|---|---|
| `home` | 首页 | **是**（缺了整个 App 没数据） |
| `detail` | 详情页 | 否 |
| `episode` | 取某一集的播放地址 | 否 |
| `search` | 搜索框 | 否 |
| `category` | 分类列表 | 否 |
| `recommend` | 「精选推荐」的更多 | 否 |
| `newest` | 「最近上新」的更多 | 否 |
| `tags` | 「全部类型」页 | 否 |
| `tag-list` | 点某个标签/胶囊之后 | 否 |

上面那张表里**只有 `home` 是硬性必填**，其余缺了就是那个入口点不动（`apiPathFor` 返回 null，不发请求也不报错）。

可用的占位符只有这七个，写别的（`{Id}`、`{cid}`）不会报错，会**原样留在 URL 里**发出去，然后 404：

| 占位符 | 值 |
|---|---|
| `{id}` | 视频 id |
| `{episode}` | 集号 |
| `{keyword}` | 搜索词。取 `query` → `keyword` → `label` → `slug` 第一个有值的 |
| `{slug}` | 标签 slug，**不经过上面那条链**，永远取原始的 `args.slug` |
| `{cateId}` | 分类的数字 id（从 `web.categories` 里查） |
| `{page}` | 页码，从 1 开始 |
| `{size}` | 第 1 页给 `firstPageSize`，之后给 `pageSize` |

`{keyword}` 和 `{slug}` 分开是有原因的：标签的 slug 通常是**数字 id**，而 `{keyword}` 会被显示名顶掉 —— 想让标签直接落到 `cate_id` 上，就得用 `{slug}`。

**有四个动作会「查不到就不发请求」**（`apiPathFor` 返回 null，前端当成一次失败）：`detail` / `episode` 缺 `{id}`、`episode` 缺 `{episode}`、`search` 和 `tag-list` 缺关键词、`category` 的 `{cateId}` 在 `web.categories` 里查不到。最后那条最要紧：不拦的话 `/api/videos` 不带过滤会返回全站，**静默给错数据比失败更糟**。

## `web.categories`

```json
"categories": { "hot": 1, "new": 2 }
```

`slug → 数字 cate_id`。值是 `{cateId}` 的来源，必须正整数。slug 只是前端用的名字，`ui.categoryIds` 里引用的就是它。

---

## `web.coverOrigin`

```json
"coverOrigin": "https://pic.drleao.cn"
```

**只有相对路径的封面才用得上它。** 接口返回 `/upload/vod/xxx.jpg` 这种相对地址时，前端把它拼成 `coverOrigin + 路径` 再交给 Java 解密取图；返回完整 `https://` 地址的话这个键不参与。

不写的话相对路径会被解析到 `appassets.androidplatform.net` 底下（WebView 自己的域），必然 404 —— 表现是封面全是占位图，而 logcat 里连一条取图请求都没有。

注意它和顶层 `cover.allowedHosts` 是**两份**，通常填同一个域名：`coverOrigin` 决定「拼给谁」，`allowedHosts` 决定「许不许取」。两处对不上时，日志里会是 `无效封面域名`。

---

## `web.firstPageSize` / `web.pageSize`

第 1 页 / 之后每页取多少条。默认 `8` / `20`。这两个值只用来填 `{size}` 占位符 —— 接口不认这个参数的话（苹果CMS 固定每页 20），写对数字只是为了让前端的翻页逻辑算得准。

## `web.ui` —— 界面

### `tabs` —— 底部导航中间那几格

```json
"tabs": [
  { "key": "hot",  "label": "热门", "icon": "fire" },
  { "key": "new",  "label": "最新", "icon": "tv" }
]
```

首页和「我的」是固定的，这一个数组决定中间。1~5 个，超过 5 个会被前端截掉。列数是按实际长度算的。

`icon` 可选值：`home` / `film` / `sparkle` / `user` / `grid` / `fire` / `tv` / `star`，认不出来退回 `grid`。

### 按 `key` 索引的四张表

`tabs` 里的每个 `key`，都得在这四张表里有一份：

```json
"categoryIds":    { "hot": ["ai-duanju", "ai-manju"], "new": ["ai-huanlian"] },
"categoryLabels": { "hot": ["成人短剧", "成人漫剧"], "new": ["AI换脸"] },
"categoryTitles": { "hot": "成人剧场",  "new": "AI专区" },
"categoryLeads":  { "hot": "短剧与漫剧，走进不同的人生。", "new": "换脸与魔改。" }
```

- `categoryIds[key]` 是一个 slug 数组，引用的 slug 必须在 `web.categories` 里存在
- `categoryLabels[key]` 是分类页顶部那一排子分类按钮的文案，**数组**，和 `categoryIds[key]` 一一对应
- `categoryTitles[key]` 是分类页大标题，**字符串**。写成数组会被插值成「电影片,连续剧,综艺片,…」几十个名字连成一串的巨标题
- `categoryLeads[key]` 是大标题下面那行小字

漏了哪张，那张就退回内置文案 —— 不报错，只是名字对不上。

### 标签相关

```json
"popularTags":      [["dushi", "都市"], ["xiaoyuan", "校园"]],
"publicPopularTags": [],
"tagGroups":        [["popular", "热门类型"], ["story", "故事题材"]]
```

- `popularTags` 是首页「全部类型 >」旁边那排胶囊，每项是 `[slug, 显示名]` 两元组。写几个显示几个，那一条是横向滚动的；内置和苹果CMS 生成的都是 8 个
- `publicPopularTags` 是另一个模式用的，现在用不上，留空数组
- `tagGroups` 是「全部类型」页的分区表，标题也在这里定。声明了的分组按配置的顺序画

⚠️ **`tagGroups` 不写死也没关系了（2026-10-18 起）**：以前页面只渲染配置里声明过的组，
对不上的标签整组消失（不报错，就是页面上少了东西）。现在配置里没声明的组会按数据补上，
标题走 `GROUP_TITLE` 兜底，实在没名字就叫「其他」。

这条改动的动机是 91porn：它的标签栏就是站点分类栏，而设备上那份
`user-source.json` 是早前版本生成的、里面根本没有 `tagGroups` —— 表现是
「标题写着 10 个标签，页面一片空」，数字对、内容没有，最难查的那种。
配置仍然应该写全（顺序和文案由你定），但漏了不会再白屏。

标签的 `group` 从哪来：接口返回 `categories: [{code, tags:[...]}]`，`code` 经 `adapters.js` 的 `TAG_GROUP_BY_CODE` 折成一个组名。**认不出来的 code 会折进 `other`** —— 所以自定义一套 code 的话，那张映射表也得一起改，否则标签全落进 `other`。

## `web.fields` —— 字段别名

```json
"fields": {
  "title": ["title", "page_h1"],
  "description": ["desc", "description"],
  "episodeNumber": ["ep_num"]
}
```

左边是 App 内部的**角色名**，右边是这个角色在接口响应里**可能叫什么**，按顺序取第一个非空值。

角色一共 16 个，全部是标量字段：

```text
id  title  cover  score  tags  description  category  episodeCount
badge  playAt  episodeNumber  source  duration  slug  tagName  code
```

两个方向都会查：代码里用了 `pick()` 但 `fields` 里没声明的角色 → 那个字段静默变空；`fields` 里声明了但代码不用的 → 多半是改名后忘了删。

**别名的边界**：它只管「这个值叫什么名字」。响应**长什么形状**（有没有 `featured`、分页塞在 `pagination` 还是别的地方）别名救不了，那部分仍然写死在 `adaptHome` / `nextPageOf` 里。

## `web.shapes` —— 响应形状映射

`web.fields` 管的是**条目里那个值叫什么**；`web.shapes` 管的是**那个值挂在哪根枝上**。
两件事分得很清：`fields` 的值是**候选键名列表**（按顺序取第一个有值的），`shapes` 的值是**路径或一个小算式**。

我们的形状是固定的（首页要 `featured`/`latest`/`cate_rec`，列表要 `items` + `pagination`，详情要 `episodes`）。站点的不一样：

```text
AGE动漫  首页   {latest, recommend, week_list}
        列表   {total, videos}          ← 没有页码数
        详情   {video:{…}, player_jx:{…}} ← 主体裹在 video 里
```

这些差异**没有一样需要计算或重排**，只是「我们的 A 在它那边叫 D」。所以能声明。

```json
"web": {
  "shapes": {
    "envelope": "",
    "home": { "featured": "recommend", "latest": "latest" },
    "list": { "items": "videos", "pages": { "div": ["total", "$pageSize"] } },
    "detail": { "root": "video", "episodes": "episodes" },
    "tags": { "categories": "categories" }
  }
}
```

### 三个可用的段

| 段 | 能映射什么 | 缺省 |
|---|---|---|
| `home` | `featured` / `latest` / `cate_rec` | 同名键 |
| `list` | `items` / `page` / `pages` | `items`、`pagination.page`、`pagination.pages` |
| `detail` | `root`（剥一层壳）/ `episodes` | 不剥、`episodes` |
| `tags` | `categories` | `categories` |

**`envelope`** 不是段，是响应最外层那个信封的名字。缺省 `data`（我们的约定）；配成空串 `""` 表示「整份响应就是我要的那个对象」。AGE动漫 的接口是裸的，就靠这一行。

### 值的两种形态

```json
"featured": "recommend"                     ← 取值路径，可以带点（video.name）
"pages":    { "div": ["total", "$pageSize"] }   ← 相除向上取整
```

`div` 只做一件事：**页数 = total / 每页条数**。分页接口基本都是这个形态（AGE动漫 全站 5666 条 ÷ 每页 24 = 236 页），而站点往往只给 `total`。

它有两个自己人操作数：`$pageSize`、`$firstPageSize`，取配置里的值。

### 为什么只有 `div`，不是表达式求值器

分界线在这儿：**声明可以枚举、可以校验；计算不行。**

`build.sh` 和 `UserSource.validate()` 都会查 `web.shapes` —— 动作名必须是认识的（`home`/`list`/`detail`/`tags`/…），值必须是路径或 `{div:[a,b]}`。拼错的键会被拦住，因为**它不会自己报错，只会静默不生效**：配置看着是对的，界面永远是空的。

再往下走一步（支持 `+`、条件、字符串拼接）就不是配置了 —— 是一门**没有工具链**的语言：写错了没有编译期检查，报错只有「某个字段是 undefined」，没有栈、没有断点、没有 IDE。而它换来的只是省掉重新打包那一步。

### 实例：一份零代码的 AGE动漫 配置

```json
{
  "origin": "",
  "web": {
    "paths": {
      "home": "https://api.agedm.io/v2/home-list",
      "recommend": "https://api.agedm.io/v2/catalog?…&order=hits&page={page}&size={size}"
    },
    "shapes": {
      "envelope": "",
      "home": { "featured": "recommend", "latest": "latest" },
      "list": { "items": "videos", "pages": { "div": ["total", "$pageSize"] } }
    },
    "fields": {
      "id": ["AID", "id"], "title": ["Title", "name"],
      "cover": ["PicSmall", "cover"], "badge": ["NewTitle", "uptodate"]
    }
  }
}
```

**没有一行代码**，2026-10-16 真机实测：首页 12 条（轮播 + 最近更新）、点「更多」翻页正常、封面 24/29 上屏。

注意 `fields` 里的**两套命名**：首页用 `AID/Title/PicSmall`（PascalCase），目录用 `id/name/cover`（snake_case）。别名按顺序取第一个有值的，所以一张表能同时管两套。

**但这站还是写了适配器** —— 卡在详情：它给的是 `playlists{源: [[集名,地址]]}`，我们要平的 `episodes[]`，那是**结构重排**，`shapes` 表达不了。见下一节。

## 声明到哪里为止

```text
① 选取      从 {D,F,O} 里拿 D 和 O                     ✅ web.fields 别名
② 改名      D 叫 A、O 叫 B                            ✅ 同上
③ 路径      D 藏在 video.name 里                      ✅ 带点的路径
④ 常量/信封  整份响应就是 data / 换个信封名            ✅ web.shapes.envelope
⑤ 映射      响应的哪根枝对应我们的哪个键               ✅ web.shapes
⑤′ 一个除法  页数 = total / size                      ✅ shapes 的 div
⑥ 结构重排  {源: [[集名,地址]]} → [{number,title,url}]  ❌ 写代码
⑦ 外部状态  解密、跨请求、签名                         ❌ 写代码
```

**⑥ 之前全能配，⑥ 之后只能写代码。** 差别不在「难不难写」，在于 ⑥ 需要**遍历 + 按位置访问**，那是程序，不是声明。

（这个分界不是拍脑袋定的：AGE动漫 卡在第 ⑥ 层，实测确认过。）

## 接口响应的形状

### ⚠️ 最外层必须有 `data` 信封

**每个 REST 响应都要是 `{"data": …}`。** `fetchApi()` 里第一件事就是查它：

```js
if (!payload || !payload.data) throw new Error('接口响应缺少 data');
```

少了这层，报的是 `接口响应缺少 data` —— 而这条错误看起来像「站点挂了」或者「路径错了」，实际上**内容和形状都对，只是没包信封**。实测踩到过（2026-10-16，拿一个自己造的静态 JSON 测绝对地址时）。

```json
{ "data": { "featured": [...], "latest": [...], "cate_rec": [...] } }
```

绝对地址那条线（`paths` 写完整 URL）不例外，同样要有信封 —— 信封是**前端**的要求，跟用相对路径还是绝对地址无关。

下面是信封**里面**那个对象该长什么样。

### 首页（`paths.home`）

```json
{
  "featured": [ 视频对象 ],
  "latest":   [ 视频对象 ],
  "cate_rec": [ { "videos": [ 视频对象 ] } ]
}
```

首页那两个列表是**拼**出来的，不用单独提供：`homepageRecommend` = `featured` 去重后接上 `cate_rec` 里各分类的视频（凑满一行），`homepageNewest` = `latest`。`paths.recommend` / `paths.newest` 是点「更多」之后才走的另一条路。

### 视频对象

```json
{
  "id": "123",
  "title": "标题",
  "cover": "https://…/cover.jpg",
  "score": "9.6",
  "tags": ["都市"],
  "desc": "简介",
  "cate_id": 24,
  "episode_count": 42,
  "badge": "更新至第 12 集"
}
```

字段名按 `web.fields` 的别名解析，上面用的是内置那套。

### 列表类（`category` / `search` / `tag-list` / `recommend` / `newest`）

```json
{
  "items": [ 视频对象 ],
  "pagination": { "page": 1, "pages": 20 }
}
```

只读 `pagination.page` 和 `pagination.pages` 两个值（别的键写了也没人看）。`page < pages` 才有下一页，`pagination` 整个缺了就当「已经到底了」。

### `detail`

```json
{
  "id": "123",
  "title": "标题",
  "cover": "https://…",
  "desc": "简介",
  "score": 9.6,
  "tags": ["都市"],
  "episodes": [ { "ep_num": 1, "title": "第 1 集", "duration": "02:31" } ]
}
```

### `episode`

```json
{ "id": "123", "ep_num": 5, "title": "第 5 集", "video_url": "https://…/index.m3u8" }
```

`video_url` 必须是可以直接播的地址（m3u8 / mp4）。要第三方解析的地址会在适配器那一步明确报错，不会静默播不出来。

### `tags`

```json
{
  "categories": [
    { "code": "popular", "tags": [ { "slug": "dushi", "name": "都市" } ] }
  ]
}
```

标签自己可以带 `group` 字段，**它的优先级高于 `code` 折出来的组名** —— 适配器在
Java 侧算好了最终组名的都该这么给（hanime1、91porn 都是）。前端读的是
`tag.group`，不走 `web.fields` 别名：那是最终值，不是「可能叫什么」的候选名之一。

`tag-list` 这条路径拿到的 `{slug}` 就是标签的 `slug`。标签如果不是真的「话题」而是
分类（91porn 就是），`tag-list` 直接指向分类列表即可：

```json
"tag-list": "/api/videos?cate_id={slug}&page={page}"
```

## 苹果CMS 型配置

这类源不用自己写 `paths` / `fields` / `ui` —— 填一个接口地址，App 探测完自动生成。存下来的配置长这样：

```json
{
  "adapter": "cms",
  "api": "https://cj.lziapi.com/api.php/provide/vod",
  "cover": { "mode": "plain", "allowedHosts": ["img.lzipic.com"] },
  "web": {
    "firstPageSize": 20,
    "pageSize": 20,
    "categories": { "1": 1, "2": 2, "6": 6 },
    "paths": { "home": "/api/home", "tag-list": "/api/videos?cate_id={slug}&page={page}&size={size}" },
    "ui": { "tabs": [ { "key": "1", "label": "电影", "icon": "film" } ] },
    "fields": { "id": ["id"], "title": ["title"] }
  }
}
```

区别在这几处：

- `adapter: "cms"` 一出现，`AiiHttp` 就把所有 `/api/` 开头的请求转给 `CmsAdapter`，由它翻译成 CMS 的 `ac=detail&pg=` / `ac=detail&t=` / `ac=detail&wd=` / `ac=list`，再把响应映射回我们的形状，外面套一层 `{"data": …}`。前端一行不用改
- **`origin` 是空的**。CMS 的地址不在 origin 上，`paths` 里那些 `/api/...` 只是内部动作名，不是真路径
- `categories` 的 slug 就是 CMS 的 `type_id`，名字是 `type_name`
- `ui.tabs` 按源自己的分类树生成：有子分类的顶层当入口，按子分类数量排前 4 个，剩下的合成「其他」；整棵树没有层级就退化成一个「影视库」
- `ui.popularTags` 是每个频道轮流挑出来的叶子分类，`tag-list` 用 `{slug}`（= `type_id`）直接查分类 —— **不能用搜索**，CMS 的 `wd=` 是标题匹配，拿「动作片」去搜一个都搜不到

返回格式两种都认：JSON 和 XML（`/at/xml/`）。XML 那边 `<class>` 只有 id 和名字、没有 `type_pid`，App 会**补问一次同门的 JSON 接口**（URL 去掉 `/at/xml/`）只取层级关系；问不到就按一维处理。

## 校验：三道闸

### 1. 拉取时（`UserSource.validate`）

拦的是「填错地址」和「明显坏掉的配置」，错误直接显示在设置页。下面是**实际文案**，照着搜代码能定位到：

| 文案 | 触发条件 |
|---|---|
| `地址要以 https:// 开头` | 不是 https |
| `只支持 https 地址（Android 默认禁止明文 HTTP，http:// 拉不下来）` | 明确写了 `http://` |
| `缺少 origin（站点入口地址）；要么补上，要么把 web.paths.home 写成 https 绝对地址` | 没写 `origin`，而且 `paths.home` 也不是绝对地址 —— 首页不知道去哪取 |
| `origin 必须是 https 开头` | origin 不是 https |
| `origin 里没有域名` / `origin 不能带用户名密码` / `origin 不能带 ?查询参数` / `origin 不能带 #片段` / `origin 只能是域名，不能带路径` | origin 不是裸域名 |
| `缺少 web 块（前端配置）` | 没有 `web` |
| `web.paths 为空（至少要有一条接口路径）` | `paths` 是空的 |
| `不认识的适配器：xxx（目前只有 cms）` | `adapter` 写了别的值 |
| `web.paths.home 缺失（首页拿不到数据）` | 没有 `paths.home` |
| `web.categories 为空（分类栏会是空的）` | `categories` 是空的 |
| `web.categories['x'] 不是正整数 cate_id` | cate_id 是 0 或负数 |
| `web.fields['x'] 的候选键列表为空` | 某个角色的别名数组是空的 |
| `cover.key 缺失（封面解不开）` / `cover.iv 缺失（封面解不开）` | `mode: "aes-cbc"` 但没给密钥 |

苹果CMS 那一型只查三条：`缺少 api 地址` / `api 地址必须是 https 开头` / `缺少 web.paths`。

### 2. 存盘前（干跑一次 `new SiteProfile`）

`SiteProfile` 的构造函数才是真正的裁判 —— 它发现坏配置的方式是**抛异常**，而那发生在 `Activity.onCreate` 里，表现是**一装完就闪退**。而配置存在 `files/` 下，App 起不来就进不了设置页，用户被一份填错的配置永久锁在外面，只能清数据。

所以在写盘之前先 `new SiteProfile(context, config)` 干跑一遍，把异常翻译成人话：

```text
这份配置会让应用启动失败，已拒绝：<原因>
```

**过了这一关的配置，装上去一定能起来。**

### 3. 打包时（`build.sh` 的配置自检）

只检查**内置的 `site-default.json`**。这几类错的共同点是**静默** —— 不崩、不报错，只是某个入口点了没反应，或者某些标签凭空消失：

```text
ui.categoryIds['x'] 里的 'y' 在 web.categories 里没有对应项
web.paths['x'] 里的 {Zz} 不是可替换的占位符
adapters.js 会产出 group='x'，但 ui.tagGroups 里没有这个分组
ui.popularTags[0] 不是 [slug, 显示名] 两元组
ui.tabs 里 key='x' 出现了不止一次
ui.tabs 有 key='x'，但 ui.categoryIds 里没有它
ui.categoryIds 有 key='x'，但 ui.tabs 里没有对应的入口
ui.categoryLabels 里少了 key='x'
adapters.js 用了 pick(…, 'x')，但 web.fields 里没有这个角色
web.fields 声明了 'x'，但 adapters.js 里没人用
```

## 症状 → 原因

| 现象 | 先查 |
|---|---|
| 首页空白 / 一直「内容更新失败」 | `paths.home` 存不存在、接口通不通；看 logcat 的 `[api] /api/home FAIL` |
| 封面全是占位图 | `cover.allowedHosts` 有没有这个域名（精确主机，或 2.0.29 起的 `pic.*.cn` 单层通配）；`cover.mode` 是不是 `aes-cbc` 而接口给的是明文图 |
| 装完就闪退 | 配置没走干跑那一关。清数据，重新在设置页填 |
| 报 `路径既不是 / 开头的动作路径，也不是 https 绝对地址` | `paths` 里有一条既不是 `/` 开头、也不是 `https://` 开头 |
| 报 `接口响应缺少 data` | **响应最外层必须是 `{"data": …}`** —— 见下面「data 信封」那条 |
| 加了 `adapter` 被拒 | `validate()` 只认 `cms`，别的值明确报错 |
| 点分类没反应 | `ui.categoryIds` 里的 slug 在 `web.categories` 里没有，`{cateId}` 查不到 → 请求不发 |
| 「全部类型」页空白 | `ui.tagGroups` 是空数组，或者标签的 `group` 折不进任何一组 |
| 标签点了没结果 | `paths['tag-list']` 是不是指向了搜索 —— 标题匹配的搜索用分类名去搜是搜不到的 |
| 子分类按钮是空的 | `ui.categoryLabels[key]` 缺了，退回内置文案了 |
| 分类页大标题变成一长串 | `ui.categoryTitles[key]` 写成了数组，得是字符串 |
| 列表翻不了页 | 响应里没有 `pagination`，或者 `page >= pages` |
| URL 里带着 `{id}` 这种 | 占位符名字不在七个里，没人替换 |
| 报 `拉取失败：认不出这是什么配置` | 贴的东西既不是我们的 JSON、也不是苹果CMS、也不是清单。**2026-10-18 起错误信息会区分原因**：超时 / HTTP 404 / 响应不是 JSON / 清单里没有 `sources` 都分开说 |
| 贴清单报 `MARKET_SOURCES` | 正常行为，前端会转成勾选列表。**如果屏幕上真出现了这七个字母**，说明前端没接住（`setup.js` 的 `offerMarket`），见[源市场清单](源市场清单.md) |

日志怎么抓：改前端用 CDP（见[真机 WebView 调试](真机WebView调试.md)）。WebView 的 `console.log` 会经 `onConsoleMessage` 转进 logcat，标签是 `AIIvideo`：

```bash
adb -s <serial> logcat | grep -E "\[api\]|\[http\]|\[source\]|\[toast\]"
```
